What if anyone could query the database, without being able to break it?

NL-to-SQL Assistant is a full-stack app that converts plain-English business questions into T-SQL using a locally hosted LLM (Ollama). A React UI shows the results table next to the generated SQL, so every answer is transparent and checkable — and a validation layer makes sure the model can only ever read approved data.

React Ollama (local LLM) sqlglot SQL Server / T-SQL MongoDB Prompt engineering

The Old Way

Every report means a ticket to whoever knows SQL. Ad-hoc questions wait in a queue, and when answers do come back, nobody can see the query behind the number.

The Assistant Way

Type the question in plain English. The model drafts the SQL, the validator checks it, the database runs it read-only, and you see the result and the query side by side.

How It Works

From question to result, every step is constrained.

01

Schema-aware prompting

The model never sees the raw database. It gets a curated catalog of reporting views, column descriptions, join rules and few-shot examples — so it can only reason about approved data.

02

Local generation

A locally hosted LLM on Ollama drafts the T-SQL. Nothing leaves the machine — no business question or schema detail is sent to a third-party API.

03

Validation before execution

sqlglot parses the generated SQL and enforces the rules: a single SELECT statement, views from the whitelist only. Input guardrails, query timeouts and row limits bound what any one request can do, and a read-only SQL Server login means even a bad query can't write.

04

Audit and evaluate

Every request is logged to MongoDB for auditing. Accuracy and latency are measured on a golden question set, and the prompts are tuned against it.

Built-In Guardrails

The interesting part isn't the SQL generation — it's what the system refuses to do.

Safe execution

Single SELECT only, view whitelist, read-only login, query timeouts and row limits — enforced in code, not in the prompt.

Full audit trail

Every question, query and result is logged to MongoDB, so any number in a report can be traced back to the exact SQL that produced it.

Measured, not vibes

A golden question set benchmarks accuracy and latency after every prompt change, so improvements are verified instead of assumed.
